# Справи — домашній центр справ

Особистий PWA-застосунок: швидко записати справу в Inbox, потім вирішити — «Сьогодні» чи «Пізніше».
Дані зберігаються локально в браузері (IndexedDB), сервера немає.

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # тести шару даних
npm run build      # статична збірка в dist/
npm run preview    # перевірити збірку (з PWA/офлайн)
```

`npm run dev:phone` відкриває dev-сервер у локальній мережі, щоб подивитися з телефона.
Встановлення як застосунку (PWA) працює тільки з HTTPS — тобто після публікації на GitHub Pages.

## Публікація (GitHub Pages)

`.github/workflows/deploy.yml` при кожному push у `main` запускає тести, збирає `dist/` і публікує його.
Один раз у репозиторії: Settings → Pages → Source: **GitHub Actions**.
Адреса: `https://<username>.github.io/home-tasks/`. Справи на сайт не потрапляють — вони лише в браузері пристрою.

Встановлення на Android: відкрити адресу в Chrome → меню ⋮ → «Додати на головний екран» / «Встановити застосунок».

## Структура

```
src/
├── app/              оболонка: роутер (#/tasks/...), верхній рядок, меню «⋯» (резервна копія)
├── features/tasks/   розділ «Справи»: вкладки, рядок, панель дій, поле додавання, друк
├── shared/           спільні панелі (Sheet / InlinePanel), повідомлення «Скасувати», утиліти
└── data/             база (Dexie), операції зі справами, резервна копія
```

Інтерфейс не звертається до бази напряму — тільки через `src/data/*`.

## Дані

- Кожен запис має випадковий `id`, `updatedAt` і `deletedAt` (м'яке видалення) — заготовка під синхронізацію.
- Схема бази версіонується в `src/data/db.ts`. Нові таблиці — тільки новою `version(N)`.

## Резервна копія

Файл `home-tasks-YYYY-MM-DD.json`:

```json
{ "format": "home-tasks-backup", "version": 1, "exportedAt": "...", "data": { "tasks": [...] } }
```

- `version` — версія формату копії (незалежна від версії бази). При зміні структури даних
  збільшується `BACKUP_VERSION` і додається крок в `upgrades` у `src/data/backup.ts`,
  тож старі копії залишаються придатними.
- «Відновити з копії» після підтвердження повністю замінює поточні дані станом із копії (`restoreBackup`).
- `mergeBackup` (новіша версія запису перемагає) — внутрішня заготовка для майбутньої синхронізації,
  з інтерфейсу не викликається.

## Майбутній розділ Tracker

Не реалізований і не показується в інтерфейсі. Місце під нього:
- `src/app/router.ts` — новий варіант `Route` (`#/tracker`);
- `src/app/App.tsx` — новий `case`;
- `src/app/Header.tsx` — назва розділу стане перемикачем «Справи / Трекер»;
- `src/features/tracker/`, `src/data/activities.ts`;
- `src/data/db.ts` — `version(2)` з таблицями `activities` і `activity_entries`
  (день відмітки зберігається як календарна дата `YYYY-MM-DD`);
- `src/data/backup.ts` — `BACKUP_VERSION = 2` і крок `upgrades[1]`.
